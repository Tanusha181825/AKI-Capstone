# Literature evidence for the ICU feature extractor

Screened PubMed, journal pages, Google Scholar-indexed results, supplements and linked repositories. The table distinguishes incident onset, progression and detection. “Unverified” means the detail was not established in the accessible source. Several publisher or PMC pages were access-limited, so this is a targeted methods review with uneven depth across studies.

## Implementation decisions

- Use the ICU clock for all rows and keep lookback separate from outcome horizon. Hourmand's 6 h stride and Tan's 6 h input show those are independent design choices. Retain Review 2's 24 h alternative as a parameter. Leave the incident/progression exclusions and any prediction gap for the label join.
- Preserve observations and counts and add two renal slopes. Different papers treat sparse values differently. A six-hour creatinine slope will often be missing because it requires two separate eligible results. Missing measurements stay null, including missing urine hours.
- Apply both source event and store timestamps. This follows the timing distinction made explicitly in the robustness audit. Represent actual documented ICU input starts using inputevents. A prescription proxy answers a different question.
- Audit cutoff-level eligibility after the label join. Creatinine and urine are inputs and KDIGO components, so near-onset windows deserve a separate analysis. A retrospective onset-based index or full-stay summary would change the task.
